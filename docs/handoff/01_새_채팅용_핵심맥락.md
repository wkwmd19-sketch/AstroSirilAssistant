# 새 개발 채팅에 전달할 핵심 맥락

다음은 새 채팅을 시작할 때 우선 읽어야 할 **2026-09-30 기준 요약**입니다.

## 프로젝트 정의

- 제품: **AstroSirilAssistant** — Siril을 기반으로 천체사진의 수동 후처리 노하우를 **단계별 반자동**으로 실행하는 Windows용 GUI/CLI 프로젝트.
- 기본 원칙: 사용자가 단계와 권장값을 확인하고 `미리보기 → 결과 확인 → 승인/적용`하도록 지원한다. 모호한 입력의 Linear/Non-linear, 캘리브레이션 여부를 임의로 단정하지 않는다.
- 기본 대상: 단일 딥스카이 이미지 후처리 및 딥스카이 FITS Light 시퀀스 전처리. 별 일주·은하수·혜성·모자이크·달/행성은 일부 스키마/프로파일은 있으나 전용 파이프라인 완성으로 간주하지 않는다.
- 기본 환경: Windows, Python/Tk/ttk, Siril 1.4.x (선호·실행 로그 1.4.4). SyQon의 설치된 Parallax/Prism 스크립트를 사용하되 앱에 서드파티 스크립트·모델을 동봉하지 않는다.

## 이미 채택된 핵심 결정

- 최신 신규 프로젝트 폴더: `D:\AstroProjects_Auto\Auto_M31_2026-09-30` (중복 시 `_02`, `_03` 추가). 구버전 `M31_2026-09-30_Auto` 읽기 유지.
- 최종 내보내기 파일: `M31_final_Auto.fits` / `.tif` / `.png` 등. **중간 작업 파일명까지 `_Auto`로 바꾸지 않는다.**
- 단일 이미지 생성 흐름: `이미지 선택 → 이미지 분석 → 메타데이터 확인·수정 → 프로젝트 생성 → 단계별 처리`.
- 선택한 원본은 `input/original`에 그대로 보존한다. 실제 처리 입력은 `input/normalized/<대상>_00_input.fits`.
- 지원: FITS, 카메라 RAW(CR2·CR3·NEF·ARW·DNG·RAF·ORF·RW2·PEF), TIFF, PNG, JPEG.
- RAW: 분리된 임시 폴더에서 Siril/LibRaw + **명시적 Debayer** 후 FITS로 표준화. 변환 결과가 없거나 불명확하면 실패; 모호한 로더 폴백 금지.
- JPEG는 손실/Non-linear, PNG·TIFF와 HISTORY 근거가 불분명한 FITS는 Linear 여부를 보수적으로 확인한다.
- 신규 단일 딥스카이 기본 순서: `Gradient → SPCC → Restoration(Parallax Nano) → Denoise(Prism Mini) → GHS → StarNet → Starless → Stars → Recombine → Final / Export`.
- Siril Richardson–Lucy/Native Denoise는 SyQon 부재 등의 폴백으로 유지. 이전 v0.13까지 진행한 프로젝트는 이미 완료한 단계를 되돌리지 않는다.
- 큰 Parallax 전체 처리에는 원본 픽셀 스케일 Safe-Band(기본 32 MiB 기준, 192px overlap) 경로가 있다. 전체 결과를 확인하고 `결과 승인`하면 동일 후보를 재계산 없이 승격한다.
- UI는 `Astro Cozy Dark`, 메인/시퀀스 공통 스타일, 화면 크기 대응 스크롤, 크기 조절 가능한 접이식 상세 로그, 실시간 로그와 `[중단]`을 유지한다.
- 각 단계는 다음 작업·요약·목적·현재 상태·추천값·주의사항·완료 기준·사용자 선택을 안내한다. 추천값은 **시작점**이며 자동 확정값이 아니다.
- 개발 전달 방식: 최신 소스를 보존하는 **전체 ZIP 우선**. Git 관리/커밋은 사용자가 다시 지시할 때 진행한다.

## 현재 기준 버전과 바로 다음 작업

- 원본 기준: `AstroSirilAssistant_v0.15.1(1).zip`.
- 현재 재현: Canon EOS RP `IMG_8284.CR3`, ISO 1600, 133.2초, 6264×4180. Siril RAW/Debayer, FITS 생성, `jsonmetadata` 명령은 성공. 이후 이미지 분석이 끝나지 않음.
- 0.15.1의 `astroauto/fits_analysis.py`에는 `fits.open(..., memmap=True, do_not_scale_image_data=False)`와 `hdu.data` 접근이 있다. 결과 FITS 헤더의 `BITPIX=16`, `BZERO=32768`, `BSCALE=1` 조합이 Astropy 메모리 매핑 읽기 실패를 유발할 가능성이 높다. **Python traceback 미제공이므로 최종 원인 확정 전**.
- 다음 핫픽스: 픽셀 데이터 읽기 시 `memmap=False` 처리 및 BZERO/BSCALE RGB FITS 회귀 테스트, 해상도·채널·원본 무결성 확인.
- 별도 점검: `jsonmetadata`의 통계 채널 키가 `\u0000...nel2`처럼 깨지는 현상; 32-bit float 작업용 FITS를 의도했으나 실제 로그에는 16-bit FITS로 저장된 현상. 현재 장애의 직접 원인이라고 단정하지 않는다.
- 오류 수정 후 **Windows + 실제 CR3 + Siril 1.4.4**에서 이미지 분석 완료, 프로젝트 생성, 출력 32-bit 여부까지 검증한다.
