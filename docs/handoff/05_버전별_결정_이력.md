## 바뀐 결정과 역사적 문서의 충돌을 다루는 방법

1. v0.14.2까지 **프로젝트 폴더** `_Auto` 접미사; v0.14.3부터 신규 프로젝트에는 `Auto_` 접두사. **최종 출력 파일** `_Auto`는 계속 유지.
2. v0.13까지 기본 Linear 순서는 Siril Denoise → RL Deblur였지만 v0.14부터 새 프로젝트는 Parallax → Prism. 이전 진행 프로젝트는 완료 상태를 보존한다.
3. v0.14.4의 FULL watchdog 초기 설정은 90초였으나 v0.14.5 Safe-Band 경로/현재 설정은 30초. 실제 값을 비교할 때는 `config/app.yaml`을 확인.
4. v0.14.8의 `이미지 분석`은 프로젝트 **생성 전**. 초기 `분석 → 프로젝트 생성` 또는 프로젝트 생성 후 분석의 이전 문서는 최신 UX보다 우선하지 않는다.
5. `README_KO.md`에는 이전 릴리스 섹션의 제목이 일부 최신 버전으로 반복 표기된 부분이 있다. 버전 귀속은 개별 `docs/*_vX.Y.Z.md`, 테스트명 및 소스 변경 이력과 대조한다.

## 사용자 결정 중 특히 보존할 내용

- 자동화 수준: **반자동**. 핵심 설정과 위험한 처리는 사용자에게 이유·주의·완료 조건을 안내하고 선택하도록 한다.
- 프로젝트/최종 결과에 `Auto` 정체성을 남긴다. 구체적인 **현재 폴더 규칙과 최종 파일 규칙은 서로 다르다**.
- 사진 처리의 기준은 실제 수행한 Siril 수동 보정 순서·도구로, 단순히 비슷한 Siril 내장 함수로 임의 대체하지 않는다.
- 다운로드/공유는 우선 **완전한 ZIP**. Git 이력 관리와 커밋/푸시는 사용자가 별도로 요청할 때 진행한다.
