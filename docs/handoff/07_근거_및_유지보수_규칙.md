- 반자동·단계 안내·상태 기록과 모호한 촬영/처리 단계의 사용자 확인.
- 각 단계의 다음 작업·요약·목적·현재 상태·추천·주의·완료 기준·사용자 선택.

- 현재는 Git 커밋/푸시를 유예하고 전체 ZIP을 우선 전달.

> 이 문서는 사용자가 이전 채팅방에 남긴 모든 문구를 자동으로 추출한 축어록이 아니다. **실제 확인 가능한 사용자 결정과 v0.15.1 소스/문서에 근거한 개발 기준을 재구성**했다. 확인되지 않은 문구·선호·실사용 성공은 채워 넣지 않는다.

## 2. 새로운 변경을 기록하는 방법

- 소스와 사용자용 문구가 함께 바뀌면 `02_요구사항_명세.md`, `03_UI_문구_및_용어집.md`를 먼저 갱신한다.
- 프로젝트명, 폴더/파일명, 입력·출력 포맷, 단계 또는 상태가 변경되면 `04_작업흐름_및_파일규칙.md`와 관련 테스트를 갱신한다.
- 릴리스마다 `05_버전별_결정_이력.md`에 변경 목적·이전 동작·새 동작·호환성·검증 상태를 추가한다.
- 버그는 `06_미해결_이슈_및_검증.md`에 **증상 → 실제 로그 → 코드상 가설 → 수정 → 테스트 → 사용 환경 재검증** 순으로 기록한다.
- 사용자가 명시적으로 요청한 내용은 `[확정/요구]`, 코드만 확인된 내용은 `[구현]`, 실사용 테스트는 `[실사용 확인]`으로 구분한다.
- 안정화 전에는 Git 이력에 임의로 푸시하지 않으며, 전 버전 ZIP을 덮어쓰지 않고 새 버전 ZIP으로 전달한다.

## 3. 아카이브 전/후 활용

- 이전 채팅방은 아카이브해도 되지만, **버전별 원본 ZIP과 이 인수인계 문서는 함께 보관**한다.
- 새 채팅의 첫 요청에 `01_새_채팅용_핵심맥락.md`와 현재 소스 ZIP을 첨부하면 개발 기준을 복원하기 쉽다.
- 이전에 논의한 세부 문구가 이 패키지에 없으면 임의로 확정하지 말고 사용자가 다시 제시한 문구를 새로운 결정으로 기록한다.
- 새 릴리스 ZIP의 `docs/handoff/`에 이 문서 세트를 복사해 **코드와 문서의 기준 버전**이 어긋나지 않도록 한다.
