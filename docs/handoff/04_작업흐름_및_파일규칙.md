# 작업 흐름·상태·데이터 및 파일 규칙

## 1. 현재 파이프라인: 시작점에 따라 분기

### 단일 이미지 / 이미 스택된 딥스카이

```text
이미지 선택
  └─ 사전 헤더 조회(FITS라면 OBJECT/DATE-OBS 등)
     └─ [이미지 분석]
         ├─ 포맷 식별
         ├─ RAW/일반 이미지라면 작업용 FITS 변환
         ├─ Siril metadata + 픽셀/헤더 통계
         ├─ Linear/Non-linear의 보수적 판단
         └─ 대상·촬영정보 사용자 확인
             └─ [프로젝트 생성]
                 └─ 원본 보존 + 정규화 FITS 프로젝트 복사
                     └─ 입력 처리 단계/Calibration 상태 확인
                         └─ (스택된 Linear이면)
                            Gradient → SPCC → Restoration(Parallax)
                            → Denoise(Prism) → GHS → StarNet
                            → Starless → Stars → Recombine → Final/Export
```

- 현재 기본 엔진 순서는 **v0.14.0 이후 Parallax → Prism**. 예전 v0.13 문서의 `Denoise → Deblur`는 이전 프로젝트 마이그레이션/폴백을 위한 역사적 순서다.
- 이미 Non-linear면 초기 Linear 전용 단계나 첫 GHS를 무조건 재적용하지 않는다.
- 단일 카메라 RAW의 Debayer·정규화는 기존에 촬영한 여러 RAW Light 시퀀스의 정식 Calibration → Debayer → Registration → Stack과 다르다.

### FITS Light 시퀀스

```text
Lights + 사용 가능한 Dark/Bias/Flat/Dark-flat
  → 파일·호환성·기존 보정 여부 확인
  → 실행 계획 생성
  → 사용자 확인/승인
  → Master Calibration
  → Light Calibration
  → Registration + 실제 seqapplyreg
  → Rejection Stack
  → 32-bit 스택 FITS
  → 단일 이미지 후처리 단계로 이어가기
```

- Dark 기본: Master Dark를 만들 때 Bias를 이중 차감하지 않는다.
- Flat 보정 우선순위: 가능한 Dark-flat, 아니면 Bias, 둘 다 없으면 경고 및 보수적 처리.
- OSC에서 CFA 처리·Debayer 시점은 Camera mode와 데이터 단계에 따라 설정한다. `AUTO`만을 근거로 강제 Debayer하지 않는다.
- 품질 지표에 의한 프레임 자동 제외는 기본 강제 동작이 아닌 제안·승인 방식.

### 특수 대상

- `STAR_TRAIL`: 별을 따라 Registration하지 않으며, 프레임 간 gap/이상 프레임과 합성 방식을 별도로 다뤄야 한다. 현재 관련 상태·프로파일과 워크플로 설계가 있음.
- `MILKYWAY`: 고정 삼각대/추적 촬영 여부, 지상/하늘 분리 스택 등이 별도 설계 항목.
- `COMET`, `PLANETARY_LUNAR`, `MOSAIC`: 전용 후처리 엔진 완성 여부를 `README_KO.md` 또는 실제 코드/테스트로 별도 확인. 설정에 존재한다고 지원 완료로 안내하지 않는다.

## 2. 프로젝트 폴더명: 최신/이전 버전

```text
프로젝트 루트: D:\AstroProjects_Auto

현재 신규 생성:
D:\AstroProjects_Auto\Auto_M31_2026-09-30
D:\AstroProjects_Auto\Auto_M31_2026-09-30_02
D:\AstroProjects_Auto\Auto_M31_2026-09-30_03

구버전 호환(열기 허용):
D:\AstroProjects_Auto\M31_2026-09-30_Auto
D:\AstroProjects_Auto\M31_2026-09-30_02_Auto
```

- `Auto_` **접두사**는 v0.14.3 이후 신규 프로젝트 폴더 규칙.
- `_Auto` **접미사**는 v0.14.2 이하 프로젝트 폴더 호환 및 Final Export 파일명 규칙.
- 중복 프로젝트가 발견되면 기존 열기 / 번호 붙여 새로 만들기 / 취소 중에서 선택하며, 기존 결과를 덮어쓰지 않는다.

## 3. 프로젝트 내부 구조

```text
Auto_<대상>_<촬영일>[_NN]/
├─ input/
│  ├─ original/               # 사용자 원본 그대로 보존
│  ├─ normalized/             # 파이프라인 입력용 FITS
│  ├─ metadata/
│  │  └─ source_metadata.json
│  └─ lights/                 # 시퀀스/이전 버전 호환
├─ calibration/
│  ├─ dark/
│  ├─ bias/
│  ├─ flat/
│  ├─ dark_flat/
│  └─ masters/
├─ working/
│  ├─ 00_calibrated/
│  ├─ 01_registered/
│  ├─ 02_stacked/
│  ├─ 03_gradient/
│  ├─ 04_color/
│  ├─ 05_restore/
│  ├─ 06_denoise/
│  ├─ 07_stretch/
│  ├─ 08_starnet/
│  ├─ 09_starless/
│  ├─ 10_stars/
│  ├─ 11_recombine/
│  └─ 12_final/
├─ output/
│  ├─ fits/
│  ├─ tiff/
│  ├─ png/
│  └─ preview/
├─ logs/
├─ temp/
└─ project.yaml
```

- 신규 단일 프로젝트는 분석·정규화 완료 후 `input/normalized/<대상>_00_input.fits`를 처리의 시작점으로 삼는다.
- `project.yaml`에는 상태, 원본/정규화 정보, 대상과 촬영 정보, 저작권, 선택 및 추천의 확인 결과를 보존한다. `logs/analysis_report.json` 등 별도 보고서를 남긴다.
- `working/` 파일은 단계번호와 목적을 사용한다. 작업 중간 파일을 모두 `_Auto` 이름으로 바꾸지 않는다.

## 4. Final Export 파일명·완료 조건

```text
working/12_final/M31_12_final.fits
output/fits/M31_final_Auto.fits
output/tiff/M31_final_Auto.tif
output/png/M31_final_Auto.png
output/preview/M31_final_Auto.jpg
```

- FITS는 선택 시 32-bit, TIFF/PNG는 선택 시 16-bit 출력이 v0.13 명세의 목표.
- Final preview와 highlight clipping을 검토한다. 원본 Recombined FITS를 보존한다.
- 출력 파일의 실재 여부를 확인한 후에만 프로젝트 상태를 `EXPORTED`로 전환하고 `최종 결과 폴더 열기` 버튼을 표시한다.
- ICC/sRGB 변환·프로필 삽입을 자동으로 강제하지 않는다.

## 5. 기본 상태와 Guard

| 단계/ID | 핵심 의미 |
|---|---|
| `INPUT_IMPORTED` / `INPUT_ANALYZED` | 입력 등록 / 이미지 분석 완료 |
| `INPUT_STAGE_CONFIRMED` | 단일 Light·시퀀스·스택 여부 확인 |
| `RAW_UNCALIBRATED` / `PRECALIBRATED` | Calibration 상태 ID. 카메라 RAW 확장자와 동일 개념이 아님 |
| `CALIBRATION_CHECKED` / `CALIBRATED` | 기준 프레임 점검 / 처리 |
| `REGISTERED` / `STACKED_LINEAR` | 프레임 정렬 / Linear 스택 결과 |
| `GRADIENT_CORRECTED` / `COLOR_CALIBRATED` | 배경·색상 보정 |
| `DEBLURRED` / `DENOISED` | Restoration·Denoise 처리; 신규 프로젝트와 구프로젝트의 실행 순서가 다를 수 있음 |
| `STRETCHED` / `STARS_SEPARATED` | GHS 적용 / 별 분리 |
| `STARLESS_PROCESSED` / `STARS_PROCESSED` | 별이 없는 이미지 / 별 레이어 각각 처리 |
| `RECOMBINED` / `FINALIZED` / `EXPORTED` | 재합성 / Final 작업본 생성 / 실제 출력 완료 |
| `REVIEW_REQUIRED` | 판단 근거 불충분 또는 사용자 확인 필요 |

안전장치: 이미 캘리브레이션된 Light의 중복 보정 금지, Linear 확인 전 초기 GHS 자동 적용 금지, 별 일주사진에 일반 딥스카이 별 정렬/스택 강제 금지. **상태머신 정의만으로 UI·엔진 구현 완료를 뜻하지는 않는다.**

## 6. Parallax/SyQon 후보·진행 규칙

- 빠른 미리보기는 기본 1536×1536 중앙 Crop, **리사이즈가 아닌 원래 픽셀 스케일 유지**.
- FULL 이미지가 큰 경우 Safe-Band 기본 활성화, bridge payload 기준 32 MiB, band overlap 192px, startup watchdog 30초 (v0.15.1 설정 기준).
- Before/After 비교는 같은 표시용 Stretch를 써야 하고 원본 Linear FITS는 수정하지 않는다.
- `전체 처리 + 결과 확인`으로 만든 FULL 후보는 설정이 동일할 때 `결과 승인`에서 정식 결과로 **승격만** 한다.
- `중단` 시 실행 중 프로세스 트리를 종료하고 취소된 임시 후보를 폐기한다.
