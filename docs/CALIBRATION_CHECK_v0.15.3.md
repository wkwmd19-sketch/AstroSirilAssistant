# v0.15.3 — 캘리브레이션 프레임 검사 단계 연결

## 이번 릴리스에서 실제 구현한 범위

- v0.15.2 `CHECK_CALIBRATION_FRAMES`는 GUI의 "이 단계의 실제 실행 UI는 이후 구현 단계에서 연결됩니다"가 보이던 예약 단계였습니다. v0.15.3에서는 단일 이미지의 `프로젝트 생성` 다음 단계에서 실제 입력 컨트롤을 표시합니다.
- `Dark`, `Bias`, `Flat`, `Dark-flat` 중 하나를 선택해 [폴더에서 등록]으로 원본 FITS 또는 카메라 RAW를 `calibration/<type>/`에 복사합니다. [프레임 폴더 열기]로 직접 넣어도 됩니다. 원본 폴더/파일을 수정하지 않으며 기존 동일 파일은 중복 복사하지 않습니다. 이름이 같은 다른 파일은 `_02` 등의 새 이름으로 보관합니다.
- [프레임 검사 / 재검사]는 프로젝트 작업용 Light를 기준으로 각 종류의 파일을 개별 검사합니다. FITS는 픽셀 데이터를 로드하지 않고 헤더에서 메타데이터만 읽습니다(`memmap=False`, `do_not_scale_image_data=True`). 카메라 RAW는 기존 Siril/LibRaw·Debayer 경로로 하나씩 임시 변환하고 검사 후 임시 파일을 제거합니다. Siril이 미설치·실패한 RAW는 **검사 오류**로 보고하며 누락 프레임으로 간주하지 않습니다.
- 해상도/채널, 카메라, ISO와 Gain을 별도로 비교합니다. Dark는 Light 노출시간·온도, Flat은 필터·Bayer·광학 정보, Dark-flat은 Flat 노출시간과 비교합니다. 누락 메타데이터는 추측으로 채우지 않습니다. 검사 대상에 서로 다른 조건의 프레임이 섞여 있으면 중앙값 하나로 덮지 않고 각 파일의 조건을 확인합니다.
- 결과는 화면에 표시되며 `logs/calibration_report.json`, `project.yaml`에 저장합니다. `CHECK_CALIBRATION_FRAMES → REVIEW_CALIBRATION_FRAMES`로 작업을 넘기며, 파일을 추가로 등록하면 기존 검사 결과는 만료되어 재검사가 필요합니다.
- `SINGLE_LIGHT`는 결과 확인 뒤 **사용자가 명시적으로 승인한 경우에만** [보정 없이 후처리로 계속]을 통해 `CALIBRATION_SKIPPED → GRADIENT_CORRECTION`으로 진행합니다. 원본 CR3와 작업용 FITS의 이미지 픽셀은 변경하지 않습니다.

## 중요한 한계

이 버전은 **캘리브레이션 프레임 탐지·호환성 검사·안전한 진행 선택**까지 구현했습니다. Master Dark/Flat 생성과 Light에 대한 실제 수치 보정은 이번 GUI 단계에 포함되지 않습니다. 특히 v0.15.x 단일 RAW는 이미 Debayer된 RGB 작업용 FITS를 만들어 두므로, CFA RAW용 Dark/Flat을 해당 RGB FITS에 자동으로 빼거나 나눠서는 안 됩니다. RAW 원본을 정식 보정하려면 Debayer **이전**의 CFA 단계부터 처리하는 엔진이 필요합니다. 캘리브레이션을 꼭 적용해야 하는 데이터는 정식 전처리 기능을 구현·검증하기 전까지 보정 없이 진행하는 옵션을 선택하지 마세요.

시퀀스의 Calibration/Registration/Stack은 기존 별도 CLI 워크플로와 구분됩니다. v0.15.3의 단일 이미지 GUI에서 시퀀스 보정을 지원한다고 표시하지 않습니다. 공유 CalibrationLibrary 자동 검색 또한 아직 구현하지 않았습니다.

## Windows에서 확인할 수용 테스트

1. v0.15.2에서 만든 **기존 프로젝트**를 [기존 프로젝트 열기]로 엽니다. `Dark / Flat / Bias / Dark-flat 검사`와 프레임 등록/검사 버튼이 보여야 합니다.
2. 4종 프레임이 없다면 [프레임 검사 / 재검사]를 눌러 모두 "없음"으로 표시되는지 확인합니다.
3. 프레임이 있다면 종류를 선택해 폴더를 등록하고 다시 검사합니다. 카메라/해상도/ISO/노출 불일치 또는 읽기 실패가 오류나 "확인 필요"로 나와야 합니다.
4. 결과 확인 화면에서 명시적으로 동의하면 Gradient 미리보기/적용 버튼으로 이어지는지 확인합니다.
5. 검사와 건너뛰기 전후 `input/original/*.CR3` 및 `input/normalized/*.fits`의 파일 내용이 변하지 않아야 합니다.
6. 여러 RAW를 검사할 때의 처리시간·Siril CLI 상태·취소 동작을 Windows 환경에서 확인합니다.

## 테스트 경계

- Python AST/설정/ZIP 검증 및 Astropy 모듈을 대신한 기존 단위 테스트 실행.
- 실제 FITS `BZERO=32768` 입출력과 Windows Siril/Canon CR3 프레임 검사 실사용은 이 빌드 환경에서 실행할 수 없었습니다. 사용자 PC 검증이 남아 있습니다.
- Git 커밋/푸시는 보류합니다.
